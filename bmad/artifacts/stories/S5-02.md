# S5-02 — Model Management (Dynamic Provider/Model Selector)

**Sprint:** S5 · **Priority:** High · **Status:** todo

## User Story

As a user, I want to browse and select from available models per provider in a searchable dropdown, so I'm not locked to a hardcoded list.

## Description

Current state: provider + model stored as free-text in Settings.

Target: Settings page shows a grouped combo/searchable list:
- **Ollama** — fetched live from local API (`/api/tags`)
- **OpenAI** — fetched from OpenAI models API (requires key)
- **Anthropic** — static curated list (API has no public list endpoint)

The chat bubble (S5-01) and the normalization trigger both read the same selected model.

> Assumed: Model selection stored as `{provider}:{model}` string in LocalSettings.
> Assumed: Fetch on Settings page open, with a manual Refresh button. No background polling.

## Acceptance Criteria

- [ ] Settings pane shows provider selector (Ollama / OpenAI / Anthropic)
- [ ] Below provider: model dropdown populated dynamically
- [ ] Ollama: calls `GET http://localhost:11434/api/tags`, parses `models[].name`
- [ ] OpenAI: calls `GET https://api.openai.com/v1/models` with API key header, filters to `gpt-*` / `o*` models
- [ ] Anthropic: static list of current Claude models (claude-3-5-sonnet, claude-3-5-haiku, claude-opus-4, etc.)
- [ ] Dropdown shows loading state while fetching
- [ ] Error state shown if fetch fails (offline / invalid key) — falls back to manual text entry
- [ ] Selected `{provider}:{model}` persisted to LocalSettings
- [ ] NormalizationService and Chat bubble both read same stored selection
- [ ] Refresh button re-fetches model list

## Out of Scope

- Multiple simultaneous provider configurations
- Per-feature model override (normalize vs chat use same model)
