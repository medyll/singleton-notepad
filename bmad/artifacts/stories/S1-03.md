# Story S1-03: SettingsService over LocalSettings (paths, window geometry)

**Status:** complete  
**Role:** Developer  
**Phase:** development  
**Depends on:** S1-02 (FileService with auto-save)

---

## Acceptance Criteria

- [ ] Create strongly-typed `AppSettings` model class with all settings properties
- [ ] Refactor `SettingsService` to use `AppSettings` model (get/set entire model)
- [ ] Add settings properties:
  - `SingletonFilePath` — path to the singleton markdown file
  - `RulesFilePath` — path to the AGENTS.md rules file
  - `Theme` — "Light", "Dark", or "System"
  - `AutoSaveDebounceMs` — debounce interval in milliseconds (default: 2000)
  - `WindowLeft`, `WindowTop`, `WindowWidth`, `WindowHeight` — window geometry
- [ ] Add default values for all settings
- [ ] Create `SettingsViewModel` with:
  - Properties bound to `AppSettings`
  - Commands for resetting to defaults
  - Validation for file paths (must be valid paths)
- [ ] Unit tests for:
  - `AppSettings` serialization/deserialization
  - `SettingsService` get/set with model
  - Default values initialization
  - Path validation
- [ ] Update `MainWindow` to use `SettingsService.GetSettings()` for initial window position
- [ ] Update `FileService` to get `SingletonFilePath` from settings

---

## Implementation Notes

- Use JSON serialization for `AppSettings` storage in `LocalSettings`
- Store the entire settings object as a single JSON string under key "AppSettings"
- Individual window geometry settings remain separate for backward compatibility
- Theme should default to "System" (follow Windows setting)
- Paths should default to user's Documents folder
- Validation: File paths must be absolute, not empty, and parent directory must exist or be creatable
