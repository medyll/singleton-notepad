# Story S1-03: SettingsService (JSON persistence)

**Status:** pending
**Role:** Developer
**Phase:** development
**Depends on:** S1-02 (FileService)

---

## Acceptance Criteria

- [ ] Create strongly-typed `AppSettings` model class with all settings properties
- [ ] `SettingsService` persists/loads `AppSettings` as JSON
- [ ] Settings file path: `%LocalAppData%\SingletonNotepad\settings.json`
- [ ] Add settings properties:
  - `NotesFilePath` — path to the singleton markdown file (default: `Documents\MY_SINGLETON_NOTEPAD.md`)
  - `Theme` — "Light", "Dark", or "System" (default: "System")
  - `AutoSave` — bool (default: true)
  - `AutoSaveDelayMs` — debounce interval in ms (default: 2000)
  - `WindowGeometry` — nested object with X, Y, Width, Height (default: 0/0/1200/800)
  - `LlmProvider` settings — provider name, endpoints, API keys, model names
- [ ] Add default values for all settings
- [ ] `SettingsService` exposes `Current` property, `Load()`, `Save()` methods
- [ ] Unit tests for:
  - `AppSettings` serialization/deserialization round-trip
  - `SettingsService` load/save with model
  - Default values initialization
  - Missing settings file → creates with defaults
- [ ] `MainWindow` uses `SettingsService.Current.WindowGeometry` for initial window position

---

## Implementation Notes

- Serialization: `System.Text.Json` with `JsonSerializerOptions { WriteIndented = true }`
- **Not** `ApplicationData.Current.LocalSettings` — use plain JSON file for testability and inspectability
- **Not** `PasswordVault` — API keys in plain JSON for Sprint 1; DPAPI encryption is Sprint 3 concern
- Directory auto-created if absent: `Directory.CreateDirectory(Path.GetDirectoryName(path))`
- Missing file on load → return `new AppSettings()` with defaults (do not throw)
