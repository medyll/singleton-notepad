# Story S1-04: MonitorHelper + window positioning

**Status:** pending
**Role:** Developer
**Phase:** development
**Depends on:** S1-03 (SettingsService with window geometry)

---

## Acceptance Criteria

- [ ] `MonitorHelper.IsWindowValidOnPrimaryMonitor(x, y, w, h)` returns true if >50% of window overlaps primary work area
- [ ] `MonitorHelper.CenterOnPrimaryMonitor(w, h)` returns `(x, y)` centered in primary work area (excluding taskbar)
- [ ] `MonitorHelper.EnsureValidWindowPosition(x, y, w, h)` returns valid position: validates or re-centers
- [ ] `MainWindow.RestoreWindowPosition()` validates saved geometry and falls back to centered if invalid
- [ ] Window geometry persists correctly across app restarts (S1-03 integration)
- [ ] Unit tests for `MonitorHelper`:
  - `IsWindowValidOnPrimaryMonitor`: valid coords, off-screen, partially off-screen
  - `CenterOnPrimaryMonitor`: output within work area bounds
- [ ] Handle edge cases:
  - Monitor disconnected since last save → center on current primary
  - Resolution changed since last save → validate and re-center if needed
  - Window would be partially off-screen → apply minimum 50% rule

---

## Implementation Notes

- Use `DisplayArea.Primary.WorkArea` (returns `RectInt32`) — **not** `System.Windows.Forms.Screen`
- `DisplayArea` is in `Microsoft.UI.Windowing` namespace (part of Windows App SDK)
- `AppWindow.Move(PointInt32)` and `AppWindow.Resize(SizeInt32)` for positioning
- `AppWindow` accessible via `this.AppWindow` in `MainWindow` code-behind
- Centering formula: `x = workArea.X + (workArea.Width - windowWidth) / 2`
- MonitorHelper should be pure static logic (no UI dependencies) for unit testability
