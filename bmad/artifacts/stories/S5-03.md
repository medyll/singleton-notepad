# S5-03 — Spell Check (Configurable, Language Detection)

**Sprint:** S5 · **Priority:** Medium · **Status:** todo

## User Story

As a user, I want configurable spell checking with automatic language detection, so I can catch typos without manually setting my language every time.

## Description

WinUI 3 `RichEditBox` has built-in spell check via `IsSpellCheckEnabled`. The editor currently uses a WebView2 (TipTap). Spell check behavior depends on which editor control is active.

> Assumed: Spell check is delegated to the browser/WebView2 spell check capability (lang attribute on contenteditable). A `spellcheck` attribute and `lang` attribute are set on the editor element.

Language handling:
- **Auto-detect** — inspect first 200 words of content, pick most likely locale, set `lang` attribute
- **Manual override** — user picks language from Settings (persisted)
- **Disable** — toggle in Settings

> Assumed: Auto-detect uses `System.Globalization.CultureInfo.CurrentUICulture` as default, with simple heuristic (common French/English stop-word frequency) for content-based detection. Full NLP not needed.

## Acceptance Criteria

- [ ] Settings > Éditeur pane has: Spell Check toggle (on/off), Language selector, "Auto-detect" option
- [ ] When enabled + auto-detect: `lang` attribute on editor set based on content heuristic on file load
- [ ] When enabled + manual: `lang` = user setting always
- [ ] When disabled: `spellcheck="false"` on editor element
- [ ] Language change in Settings applies immediately (no restart)
- [ ] Setting persisted in LocalSettings
- [ ] At minimum French (fr-FR) and English (en-US) supported
- [ ] Status bar shows active spell-check language when enabled

## Out of Scope

- Custom dictionary
- Grammar checking
- More than basic locale detection heuristic
