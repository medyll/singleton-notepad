# S6-01 — Inline Diff in WebView (Git-Style, Replace DiffOverlay)

**Sprint:** S6 · **Priority:** High · **Status:** todo

## Context & Motivation

The current diff preview is a WinUI 3 `InlineDiffEditor` UserControl rendered as a full-screen overlay (`DiffOverlay`) that hides the editor entirely. This was a workaround for RichTextBox limitations. The editor is now a WebView2/TipTap instance, which can render rich diffs natively with full HTML/CSS control.

**What exists to delete:**
- `Views/Controls/InlineDiffEditor.xaml` + `.cs` — WinUI UserControl, ~200 lines
- `DiffOverlay` Border in `MainPage.xaml` — full-screen opaque overlay
- `ShowDiff()` / `HideDiff()` in `MainPage.xaml.cs`
- `DiffLineViewModel` class (brush-per-line GC pressure)
- `DiffViewer.ApplyClicked` / `DiffViewer.CancelClicked` event wiring in `MainPage.xaml.cs`
- `SideBySideDiffBuilder` usage in `NormalizationService` (replaced by unified diff or raw strings)

**Current limitations:**
- Full-screen overlay = disorienting, loses editor context
- Line-level only (no word/char diff)
- 200-line hard render cap with "..." truncation
- `new SolidColorBrush()` per line (GC pressure, no virtualization)
- No context lines (unchanged lines around changes not shown)

## Proposed Design

### Principle
The WebView already owns the editor surface. Give it the diff to render — no WinUI overlay needed. The diff is shown **in place** inside the editor WebView, with the editor in a read-only "diff review" mode.

### Visual Style (git-style)
```
  [unchanged line]
- [deleted line — red background, strikethrough]                ← old content
+ [inserted line — green background]                            ← new content
~ [modified line — split: red left / green right, word-level]  ← modified
  [unchanged line]
```

Context: show 3 unchanged lines before/after each change hunk (like `git diff -U3`).

Word-level diff on modified lines (like `git diff --word-diff`): deleted words in `<del>`, inserted words in `<ins>`.

### Data Flow
1. `NormalizationService.NormalizeAsync` computes a **unified diff** (line-level + word-level for modified lines) as a JSON-serializable structure. No more `SideBySideDiffModel`.
2. `MainPage` sends diff payload to WebView via `PostWebMessageAsString`:
   ```json
   {
     "type": "showDiff",
     "hunks": [
       {
         "context_before": ["line", "line", "line"],
         "changes": [
           { "kind": "del", "text": "old line", "words": null },
           { "kind": "ins", "text": "new line", "words": null },
           { "kind": "mod", "old": "old text", "new": "new text",
             "old_words": ["keep ", "-changed-", " keep"],
             "new_words": ["keep ", "+new+", " keep"] }
         ],
         "context_after": ["line", "line"]
       }
     ],
     "stats": { "added": 3, "deleted": 2, "modified": 5 }
   }
   ```
3. `editor.html` JS receives `showDiff` message → replaces editor content with rendered diff HTML → editor goes read-only.
4. User clicks **Appliquer** or **Annuler** → JS sends `{ "type": "applyDiff" }` or `{ "type": "cancelDiff" }` → `MainPage` handles, restores editor to normal mode.

### Apply/Cancel UX
- Floating action bar rendered **inside the WebView** at top of diff view (not a WinUI overlay).
- Bar shows: `✓ Appliquer` (green) · `✗ Annuler` · stats (`+3 -2 ~5`).
- Bar is sticky (stays at top while scrolling diff).
- On Apply: WebView sends `applyDiff` → `MainPage` sets `EditorContent = NormalizedContent` → sends `{ "type": "clearDiff" }` to WebView.
- On Cancel: WebView sends `cancelDiff` → `MainPage` clears `PendingNormalization` → sends `{ "type": "clearDiff" }`.

### NormalizationResult changes
Remove `SideBySideDiffModel Diff` property (DiffPlex dependency in model).
Add `DiffPayload DiffJson` — the JSON-ready structure above.
`NormalizationService` computes `DiffJson` using DiffPlex internally, converts to the payload format.

## Acceptance Criteria

- [ ] No `DiffOverlay` in `MainPage.xaml` — diff shown inside WebView
- [ ] `InlineDiffEditor.xaml/.cs` deleted
- [ ] Diff renders with context lines (3 before/after each hunk)
- [ ] Deleted lines: red background + strikethrough
- [ ] Inserted lines: green background
- [ ] Modified lines: word-level highlight (red word del, green word ins)
- [ ] Floating "Appliquer / Annuler / stats" bar inside WebView, sticky at top
- [ ] Apply: replaces editor content, exits diff mode
- [ ] Cancel: discards, restores original content in editor, exits diff mode
- [ ] No 200-line render cap (full file diffable)
- [ ] Dark/light theme aware (diff colors adapt)
- [ ] Editor read-only while diff is displayed (no accidental edits)

## Out of Scope

- Side-by-side (split) diff view
- Per-character diff (word-level is sufficient)
- Diff persistence across sessions
