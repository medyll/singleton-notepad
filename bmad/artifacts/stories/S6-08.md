# S6-08 — Intégration des Skills (Chat + Éditeur)

**Sprint:** S6 · **Priority:** High · **Status:** todo

---

## Vision

Le notepad est un point d'entrée unique vers un monde multiple. Sa puissance est cachée : l'utilisateur n'a pas besoin de savoir quels skills s'activent — ils s'activent seuls si pertinents. L'invocation manuelle reste possible pour le contrôle explicite.

---

## Format d'un Skill

Chaque skill = un fichier `.md` dans le dossier configuré.

```markdown
---
name: analyse-financiere
description: Analyse des données financières, bilans, tableaux de chiffres
tags: [finance, bilan, tableau, chiffre, analyse]
version: 1.0
---

Tu es un expert financier. Quand on te présente des données chiffrées ou un bilan :
- Identifie les tendances clés
- Signale les anomalies
- Produis un résumé structuré en markdown
```

**Frontmatter requis :**
- `name` (string) — identifiant unique, sans espaces
- `description` (string) — phrase courte, utilisée dans l'UI et pour le matching
- `tags` (string[]) — mots-clés pour l'auto-sélection

**Frontmatter optionnel :**
- `version` (string) — pour le debug
- `always` (bool, défaut `false`) — si `true`, skill injectée sur CHAQUE requête (ex: skill de persona globale)

## Découverte des Skills (`SkillService`)

### Interface

```csharp
public interface ISkillService
{
    IReadOnlyList<SkillDefinition> LoadedSkills { get; }
    Task ScanAsync(string skillsPath, CancellationToken ct = default);
    IReadOnlyList<SkillDefinition> SelectForContext(string userMessage, string? documentContext);
    SkillDefinition? GetByName(string name);
}
```

### `SkillDefinition` (modèle)

```csharp
public class SkillDefinition
{
    public string Name { get; set; } = string.Empty;
    public string Description { get; set; } = string.Empty;
    public List<string> Tags { get; set; } = [];
    public bool Always { get; set; }
    public string Content { get; set; } = string.Empty; // corps du .md sans frontmatter
    public string FilePath { get; set; } = string.Empty;
}
```

### `ScanAsync`

1. Lire `settings.SkillsPath` — si vide ou dossier inexistant → `LoadedSkills = []`, log warning
2. Glob `*.md` dans le dossier (non-récursif)
3. Pour chaque fichier : parser le frontmatter YAML (bloc entre `---`), extraire `Content` (tout après le 2ème `---`)
4. Ignorer les fichiers sans frontmatter valide (log warning par fichier ignoré)
5. Mettre en cache dans `LoadedSkills`
6. Rescanner si le dossier change (`FileSystemWatcher` sur le dossier, debounce 500ms)

### `SelectForContext`

Algorithme **tag-match + keyword-match** — déterministe, 0 appel LLM, < 1ms :

```
score(skill, message, docContext) :
  combined = toLower(message + " " + (docContext ?? ""))
  score = 0
  foreach tag in skill.Tags:
    if combined contains tag → score += 2
  if combined contains skill.Name → score += 3
  foreach word in skill.Description.Split():
    if combined contains word (len > 4) → score += 1
  return score
```

Règles de sélection :
- `Always = true` → toujours incluse, score ignoré
- `score >= 2` → incluse
- Max **3 skills** simultanées (pour ne pas saturer le context window)
- Si aucun match et aucune `Always` → 0 skills (pas d'injection parasite)

## Injection dans le LLM

### `ChatService.SendAsync` — modification

```csharp
public async Task<string> SendAsync(string userMessage, string? contextContent,
    ChatMode mode, CancellationToken ct = default)
{
    var settings = await _settingsService.LoadAsync(ct);

    // 1. Sélectionner les skills pertinentes
    var skills = _skillService.SelectForContext(userMessage, contextContent);

    // 2. Construire le system prompt
    var systemPrompt = BuildSystemPrompt(contextContent, skills);

    // 3. Résoudre le provider
    var providerName = !string.IsNullOrEmpty(settings.ChatLlmProvider)
        ? settings.ChatLlmProvider : settings.LlmProvider;
    var provider = _providerSelector.GetProvider(providerName) ?? _providerSelector.Current;

    return await provider.CompleteAsync(systemPrompt, userMessage, ct);
}
```

### `BuildSystemPrompt` avec skills

```
[SKILLS ACTIVES]
--- skill: analyse-financiere ---
Tu es un expert financier. Quand on te présente...
--- fin skill ---

[CONTEXTE DOCUMENT]
<contenu_note>
...
</contenu_note>

[INSTRUCTIONS]
Tu es un assistant d'écriture...
```

Ordre : skills en premier → contexte document → instructions générales.

## Invocation Manuelle

Dans la zone de saisie du chat, l'utilisateur peut taper :

```
/analyse-financiere Voici mon bilan Q3...
```

- Parser `/skill-name` en début de message
- Forcer l'inclusion de cette skill (même si score = 0)
- Retirer le `/skill-name` du message envoyé au LLM
- Si la skill n'existe pas → afficher dans le chat : `⚠ Skill "analyse-financiere" introuvable`

## NormalizationService — skills injectées en supplément

Si `SkillsPath` est configuré et des skills matchent le contenu du document :
- Les skills `Always = true` sont injectées en préfixe du system prompt de normalisation
- Les skills avec tag `normalisation` ou `writing` sont incluses si score ≥ 2
- Injection après les règles AGENTS.md (skills = instructions générales, AGENTS.md = règles spécifiques au document)

## Acceptance Criteria

- [ ] `SkillService.ScanAsync` lit tous les `.md` avec frontmatter valide dans le dossier configuré
- [ ] Skills sans frontmatter ignorées silencieusement (log, pas crash)
- [ ] `SelectForContext` retourne max 3 skills, score ≥ 2 ou `Always = true`
- [ ] `Always = true` injectée sur chaque message
- [ ] `/skill-name` force l'inclusion de la skill nommée
- [ ] `/skill-name` inexistante → message d'erreur dans le chat
- [ ] `SkillsPath` vide → aucun effet, 0 skills
- [ ] Skills affichées sous le message assistant (noms + tooltip description)
- [ ] `SkillsPath` dans Settings avec FolderPicker + compteur
- [ ] FileSystemWatcher relance ScanAsync sur changement du dossier (debounce 500ms)
- [ ] Skills `Always` injectées dans NormalizationService
- [ ] Build 0 erreur 0 warning

## Out of Scope

- Recherche sémantique / embeddings
- Dépendances entre skills
- Skills distantes (HTTP) — fichiers locaux uniquement
- Éditeur de skills intégré (édition dans l'app)
